# 首次安装（Edge / Chrome）

这是“网页资料收集助手 · 本机连接”配套扩展。普通 Cookie 导出插件可以保留，但不能替代本连接扩展。

1. 在您平时已登录目标网站的 Edge 中打开 `edge://extensions`。
2. 开启“开发人员模式”，点击“加载解压缩的扩展”。
3. 选择本 README 所在的整个 `browser-extension` 文件夹（不要选择某个文件）。
4. 用同一个 Edge 个人资料打开 `http://127.0.0.1:18765/`，刷新页面。
5. 填网址并点击“开始收集网页”。首次访问一个网站时，按提示点击工具栏中的配套扩展并允许该网站。等待中的任务会自动继续（最多等待 2 分钟，可以取消），超时或取消后需重新点击收集。

以后该网站的 Cookie 会在点击收集时后台同步，不需要弹出独立浏览器，不需要复制粘贴。
默认浏览器是 Chrome 时使用 Chrome；其管理地址为 `chrome://extensions`，使用同一份扩展，无需修改代码。启动器按操作系统 HTTP 关联打开工具，不固定 Edge。
页面会显示 Windows 默认浏览器以及实际连接的浏览器。Windows 以外不保证识别默认浏览器名称，但仍按系统默认方式启动。
不支持 Firefox，也不会跨浏览器或跨个人资料读取登录状态。
如果在内置预览浏览器打开工具，无法读取 Edge 的扩展，必须在 Edge 中打开工具页面。

如果已经安装旧版配套扩展：在浏览器扩展管理中点击本扩展的“重新加载”，再刷新工具页面（安装在解压副本的用户需先用新版文件替换该扩展副本）。当前版本 1.5.3。

1.4.1：按钮改为“保存并下载 Markdown”，保存后直接下载以文章标题命名的文件，不切换文章标签页，不需要新增下载权限。按 Ctrl+J 查看下载，采集记录仍保留在工具中。

1.4.0：新增“采集当前标签页正文”。保持本机工具页面打开，在文章标签页手动完成验证并看到正文后，点击扩展图标和该按钮；直接保存当前页面并切回工具下载，不重新请求文章。需要确认新增的标签页读取权限。微信公众号仅提取正文区域，验证页不保存；图片保留原链接，此方式不下载图片。正文仅发往本机工具，不上传第三方。

1.3.0：输入完整网址、停止输入 0.65 秒后自动检查授权。已授权的网站直接后台同步，无需点击采集，不弹窗口，不访问目标网站正文。未授权时显示“授权本站并同步”，点击后才打开授权窗口。Cookie 存在不等于网站确认已登录。
刚成功同步的状态复用 30 秒，避免立即点击采集时重复等待。切换网址会重新检查（同网址 30 秒内复用）；返回工具时也会检查。
“改用手动 Cookie”会展开输入框并关闭后台同步。手动导入先等待正在进行的输入同步结束，再保存手动内容，避免互相覆盖；不会自动开启正文采集。

1.2.0：首次需要授权时自动打开扩展授权窗口。点击其中“允许后台获取本站 Cookie”，再确认浏览器权限提示。
若没有看到窗口，可点击采集按钮下的“打开授权窗口”。已有网站授权则不会打开窗口。
页面会区分等待授权、同步 Cookie、网页采集三个阶段；授权后每 0.5 秒检查继续，单次同步最长等待 8 秒。
手动 Cookie 导入已默认折叠。旧版扩展需更新后才能使用此流程。

## 数据范围

- 仅允许本机 `127.0.0.1:18765` / `localhost:18765` 的根页面发起请求。
- 首次按网站授权，不默认授予全部网站访问权限。
- 只读取当前网址适用的 Cookie（包含 HttpOnly），排除不支持的分区 Cookie。
- 不读取密码、历史记录、其他网站 Cookie；不读取 LocalStorage 或 IndexedDB。
- Cookie 从扩展直接发送给本机受令牌保护的导入接口，不返回网页、不存入扩展、不上传外网。
- 会话按现有工具机制保存到本机 sessions 文件夹，请勿分享或打包该文件夹。
- Cookie 存在不等于登录有效，也不能解除会员权限或网站访问限制。
- 支持批量任务中明确填写的网址，不会自动扫描全部网站。取消“收集时后台同步当前浏览器的本站 Cookie”后不会读取。
- 可在扩展管理中撤销站点权限或移除此扩展。

权限设计参考：[Chrome Cookies API](https://developer.chrome.com/docs/extensions/reference/api/cookies)、[可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions)。

1.5.3：支持本机工具的“按作者批量下载”。按站点授权后，由工具驱动作者列表滚动和文章保存；遇验证暂停，人工处理后继续。保留进度和去重，每篇 Markdown 合并为 ZIP。只包含可发现、可访问的内容，不保证全部历史。

批量任务现在由同一个工具页复用一个后台工作标签页，跨作者、列表和正文阶段复用，不按文章数量累积标签页；遇验证才激活工作页。只操作扩展创建的工作页，不替换日常标签页。

资料包同时包含 `documents.jsonl`（UTF-8，每行一篇文章）、每篇 Markdown、采集清单及 RAG 导入说明。JSONL 保留 document_id、source_url、platform、author_id、title、text、markdown、captured_at、content_hash、partial_content 和图片链接。作者名称和发布时间未可靠提取时为 null；采集时间不能当作发布时间。旧记录的采集时间可能为空。建议入库时按标题／段落切块，再生成向量；可在本机工具中另行下载图片或使用 MinerU 云端识别图片（需要本机配置 API 凭据），不生成 embedding。

本机网页可选择 RAG 资料保存目录。文件夹模式直接由本机服务写入 JSONL 和 Markdown，并写入 export.json 就绪标记；无需浏览器决定下载路径。保存设置在网页完成，无需扩展增加文件系统权限。

新版保留页面明确提供的作者和发布时间元数据；更新扩展后请重新加载。


历史发现与自动处理更新：新版扩展支持下一页、加载更多、内部滚动容器；滚动未到底时不会因 6 轮无新增而结束。只有达到篇数上限或页面连续确认末尾才自动保存正文；卡住时暂停并提示检查，不冒充全部完成。历史任务可在详情中“继续发现历史”，保留已保存文章，从新增链接继续。

新任务默认启用“采集完成后自动识别图片并保存资料”。后端串行排队调用 MinerU，使用任务开始时选择的目录；关闭网页不会中止后处理，服务重启会恢复排队或未完成的后处理。识别失败仍保存成功资料和错误标记，提供“重试识别并保存”。浏览器下载模式需要网页保持打开；需要完全后台保存请选本机目录。该更新需要重新加载 Cookie-Editor 1.14.3 或独立版 1.5.3。
