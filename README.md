# 网页资料收集助手 2.1

## Windows 免安装版

请在本仓库的 [Releases 下载区](https://github.com/wzeffort/UnifiedSpider/releases) 下载 **WebCollector-Ready** 压缩包，不要把 GitHub 自动生成的 Source code ZIP 当作便携版。全部解压后双击“启动.bat”，首次启动会在本地准备内置环境，无需安装 Conda、Python 或 Docker。适用于 Windows 10/11 64 位；首次准备完成后若要换目录，请重新解压原包。

源码中的 start.bat、install.bat 和打包脚本保留了开发机环境路径，直接使用源码时需要按自己的环境调整，也可安装 requirements.txt 和 Playwright Chromium 后执行 `python app.py`。便携版不依赖这些开发机路径。不要公开上传 sessions、browser_profiles、data 或 Cookie 导出文件。

当前默认流程为“粘贴网址 → 开始收集 → 下载资料”。输入网址后，已授权网站通过扩展后台同步 Cookie，并显示获取结果；正文仍需点击“开始收集网页”。插件下载和安装说明统一放在“首次连接 / 扩展未就绪时看这里”。“手动导入本站 Cookie（备用）”默认折叠，保留 JSON 粘贴框、文件选择和导入按钮，不再重复显示插件下载及安装说明。

会员提示不再自动中止：正常返回且有可见正文时，保存可见文字与图片，并在页面、Markdown、TXT、图文包中注明“部分内容／试读”。自动采集的表格记录也注明内容范围。只有错误响应、登录验证或没有足够可见正文时才保留为失败或待处理，不获取尚未授权的隐藏全文。

## 图片与离线阅读

### 微信验证后直接保存当前标签页

遇到“环境异常／完成验证后即可继续访问”时，工具会提示验证，不再将该页面当作正文保存。Cookie 导入不代表已通过环境验证。

1. 从本机工具重新下载配套扩展并解压。在 Chrome／Edge 的扩展管理中加载新目录，或替换原目录后点击“重新加载”。旧版扩展没有此按钮；新增的读取当前标签页权限需要浏览器确认。
2. 在同一个浏览器保持 `http://127.0.0.1:18765/` 打开，再打开公众号文章，手动完成验证，确认正文已显示。
3. 保持文章标签页处于当前页，点击浏览器工具栏的配套扩展，再点击“保存并下载 Markdown”。两个配套扩展均支持此功能。
4. 保存成功后自动发起 Markdown 下载，文件名包含文章标题，无需切回工具再次下载。可按 Ctrl+J 查看下载；工具的“以前收集的内容”仍保留记录。

此功能读取当前页面已显示的正文，不重新请求文章，不需要先同步 Cookie。微信公众号只提取 `#js_content`，未找到正文时提示失败。不会自动处理验证码，也不保证浏览器一定能通过验证。图片保留原链接，本次直接保存不下载图片，不保证离线看图；超过约 1.9 MB 的页面请改用复制正文保存。

登录状态：在操作浏览器里自行登录后，可点击“保存本站登录状态”，无需先成功采集正文。若常用浏览器已登录，可从 [Cookie-Editor 官方网站](https://cookie-editor.com/) 安装扩展，在目标网页导出本站 JSON，直接粘贴到主页面的 Cookie 输入框，或选择本地 JSON 文件导入。导入会替换本工具保存的本站状态，忽略其他域名、过期及不支持的记录，不代表权限或验证码已通过。若导入了不同且适用于当前网址的新凭据，会解除本站的本地冷却，允许立即重试；相同凭据、仅更改过期时间或不适用于当前路径的 Cookie 不解除冷却。若网站再次拒绝，重新累计拒绝次数，连续 3 次后暂停 5 分钟。导入前先关闭操作浏览器。Cookie 相当于临时登录凭证，不要分享、上传聊天或提交代码仓库；用完请自行删除导出文件。扩展应只授予需要的网站权限，可用后禁用或卸载。

采集时自动下载正文 img 图片，支持常见懒加载地址、相对地址和重复图片去重。下载区保留 Markdown，并新增“下载图文包（含图片）”。解压全部文件后双击“打开阅读.html”，即可离线查看正文和已保存图片；也可以打开“正文.md”，请保留旁边的 images 文件夹。

每页最多下载 40 张，每张最多 8 MB，每个任务图片总量最多 100 MB，每页图片下载总预算约 60 秒。支持 JPG、PNG、GIF、WebP；暂不包含背景图、视频及内嵌 data 图片。图片下载失败会保留原链接并在“图片说明.txt”列出，不影响正文。单独下载的 Markdown 使用原图链接，离线看图请选择图文包。

图片请求不会发送保存的账号 Cookie；需要额外授权或防盗链验证的图片可能失败。旧任务需重新采集才会保存图片。已用本机测试站验证图片采集、去重、失败处理、ZIP 实际下载和离线 HTML 图片显示；不保证所有网站图片都能下载。

## 这次完善了什么

- 输入网址后，明确提示本工具是否有适用于本站的浏览状态。勾选复用不会自动登录。
- 需要登录的网站优先通过已授权扩展同步本站 Cookie，失败时可改用手动粘贴或 JSON 文件导入。
- 操作浏览器使用专用持久化资料目录，关闭后保留 Cookie/站点存储；确认保存时导出 Cookie、localStorage 和 IndexedDB，供后台使用。
- 识别 HTTP 200/HTML pre 包装里的 JSON 错误，例如知乎 error.code=40362，避免误判成正文。
- 同站连续被拒绝 3 次后暂停 5 分钟，跨任务生效；不对 403、429 自动连发重试。成功采集或导入新的适用凭据可清除本地失败计数，但不代表网站已经解除自身限制。
- 知乎文章/回答优先提取相应正文区域；发现折叠内容或无法定位时提示核对完整性。

浏览器资料位于 browser_profiles，后台状态快照位于 sessions。两者都只用于本工具，按来源地址隔离，请勿分享。
www.zhihu.com 和 zhuanlan.zhihu.com 的资料分别保存，不能因一个成功就认为另一个已登录。

## 给使用者：只需三步

1. 双击本目录的 **start.bat**，打开 http://127.0.0.1:18765。
2. 粘贴网页地址，点击“开始收集网页”。
3. 完成后优先下载 Markdown；需要离线看图时选择“下载图文包”。TXT、CSV 和 JSON 在更多下载选项中。

启动时不安装依赖，无需 Docker 或 npm。正在运行时再次双击只会打开已有界面。

### 遇到登录或验证怎么办？

优先使用下文的扩展自动同步，或展开“手动导入本站 Cookie（备用）”粘贴 JSON / 选择文件导入。需要人工处理页面时，可在“更多选项与帮助”中展开“需要登录或验证？打开浏览器处理”，点击“打开操作浏览器”。
在弹出的独立浏览器里 **由您自行登录或验证**。看到正文后，回工具点击“已看到正文，保存当前页面”。

工具保存当前可见页面和该站浏览状态；之后收集同一来源地址的网站时，可勾选“使用本工具已保存的本站登录状态”。保存浏览状态不等于登录一定有效，网站仍可能拒绝访问。
不会读取日常浏览器的个人资料，也不会代填账号密码。仍被网站拒绝时会明确提示；不保证所有站点均可通过。
登录状态只存放在本机 sessions 目录，请勿将该目录分享给他人。

### 多个网址、翻页、动态页面

在“更多采集设置”中：
- 批量网址：每行一个，最多 100 个；填写后优先使用批量网址。
- 采集范围：单页、同站链接、下一页链接。
- 最多页数：1–100；批量输入时不少于输入网址数。继续采集仍受总页数限制。
- 自动方式：Scrapy 读取静态网页，遇到空白或需要等待/滚动的页面切换浏览器。
- 浏览器渲染：适合动态正文、自动方式获取不完整的页面。
- 等待内容出现：可填写 CSS 选择器；不熟悉时保持默认。
- 下一页：支持带 href 的同站链接；不支持任意 JavaScript 按钮录制。

### 任务与结果

两个任务同时执行，其余排队，最多 20 个待执行/运行任务。
任务运行显示进度，历史中可取消或继续/重试。
成功页面逐页保存，某页失败不会丢失之前结果。“部分成功”只导出成功部分，失败页面在历史详情及 JSON 中列出。
服务重启会将未完成任务显示为“已中断”，手动点击继续；不会偷偷重新发送请求。
单次任务最多运行 30 分钟，取消或超时后可继续，已成功页面不重复抓取。

表格需要指定列时，可展开“高级设置”，点选快照内容、设置字段规则；复杂列表可配置记录容器，不熟悉时保持默认。

## 给维护者：后台架构

- FastAPI + Uvicorn：本机后台 REST API，接口文档 /docs。
- Scrapy：真实 HTTP 下载器进程，压缩、超时、两次临时失败重试；403 不反复重试。
- Crawl4AI + Playwright：动态渲染、滚动、等待内容；按站点使用已保存会话。
- Playwright 可见浏览器：人工处理登录/验证，明确确认后捕获正文。
- BeautifulSoup + markdownify：正文清理、CSS 字段提取、Markdown 转换。
- 有界线程任务队列 + 独立采集子进程：JSON 持久化、检查点、取消、恢复。

每个任务内页面顺序处理并间隔 1 秒；HTTP 下载使用独立 Scrapy 进程。这是面向本机中小规模采集的实现，不是分布式高吞吐集群。
数据位于 data；登录状态位于 sessions；每个任务的 worker.log 和 session.log 用于排错。
只绑定本机 18765；POST 接口需要从页面获取的本机请求令牌。

### 重试与自动保存 Cookie

启动器自动使用系统默认浏览器，不固定 Edge：默认 Chrome 则打开 Chrome，默认 Edge 则打开 Edge。
Cookie 来源是实际连接扩展的浏览器个人资料，不会跨浏览器或个人资料读取。
推荐在日常已登录的 Edge / Chrome 中安装 `CookieEditor-Collector` 本机收集版，
用同一个浏览器个人资料打开本机工具。输入网址后，已授权网站自动后台同步该网址适用的 Cookie，无需点击采集或重新登录；未授权时提供明确的授权入口。
同步 Cookie 不会自动访问目标网站采集正文，正文仍由用户点击“开始收集”触发。

仅支持本机 18765 端口；内置预览浏览器无法读取 Edge 的扩展。
不扫描浏览器全部 Cookie，不修改个人浏览器配置；批量任务按明确填写的网站分别同步，
同站不同路径的 Cookie 合并保存。暂不自动同步任务运行时新发现的其他站点。
页面已移除仅打开网页的默认浏览器按钮。取消后台同步可使用之前导入的状态或采集公开页面。

同一站点连续拒绝 3 次才暂停 5 分钟；前两次可以检查登录状态后手动重试。
不会对 403、429 自动连发重试。成功保存正文、导入新的适用状态会清除失败计数；
5 分钟没有新增拒绝记录也会重新计数。等待期间误点不会延长时间。
手动保存已打开页面不算新的网络请求，不增加拒绝次数。

工具不直接读取日常 Chrome/Edge 的 Cookie 数据库，不自动输入账号密码，也不保证 Cookie 一定有效。本站状态仅保存到本机；不要分享 Cookie、导出文件或 sessions 目录。

## 按作者批量下载（浏览器扩展模式）

在本机网页顶部的“按作者批量下载”中，每行输入一个作者入口，点击“开始批量收集”。请在已安装新版配套扩展的同一个 Edge／Chrome 个人资料中打开工具，不能用侧边预览页操控 Edge 的扩展。

- 雪球：输入作者主页，例如 `https://xueqiu.com/u/作者数字ID` 或 `https://xueqiu.com/作者数字ID`。程序滚动当前列表、尝试可见的“下一页／加载更多”，只保留此作者的帖子链接，然后逐篇打开并保存正文。需完整历史时，请先确认列表处于“全部”和按时间排列，而非“热门”或筛选分类。
- 微信：输入可在浏览器访问的历史列表 `/mp/profile_ext` 或合集 `/mp/appmsgalbum` 地址。只保存当前列表可发现的文章；合集不是整个公众号。输入 `/s/...` 单篇文章只保存这一篇，不会自动推导全部历史。仅凭公众号名称不能可靠解析账号，也没有实现任意公众号的全量历史接口。
- 多作者依次处理。每个作者默认最多 500 篇，可设置 1–5000。每次间隔至少 3 秒；连续 6 轮没有新链接、达到篇数上限或 500 轮加载后停止发现，停止不等于已加载全部历史。也可点“停止发现，下载已发现文章”。
- 遇登录／验证或正文无法定位时暂停。请在扩展打开的标签页处理，回工具点击“继续”；不便处理可“跳过当前文章”，跳过原因进入清单。暂停、刷新或服务重启后保留进度，刷新后需手动继续；重复链接不重复保存。
- 默认每个作者本轮结束后自动下载合集 ZIP（可取消勾选）。也可点击任务的“下载 Markdown 合集 ZIP”，每篇一个按标题命名的 Markdown，并附已发现／已保存／未处理／跳过的清单。任务未完成也可下载已保存部分。图片保留原链接，不保存图片文件。

本功能仅操作浏览器可见页面，不获取隐藏／未授权内容，不保证反爬验证能通过，也不保证作者全部历史完整。已用隔离浏览器和模拟页面测试流程；真实站点页面结构变化可能导致暂停。新版扩展版本：独立连接版 1.5.3、Cookie-Editor 本机版 1.14.3。替换文件后请重新加载扩展并刷新本机工具。

批量任务现在由同一个工具页复用一个后台工作标签页，跨作者、列表和正文阶段复用，不按文章数量累积标签页；遇验证才激活工作页。只操作扩展创建的工作页，不替换日常标签页。

资料包同时包含 `documents.jsonl`（UTF-8，每行一篇文章）、每篇 Markdown、采集清单及 RAG 导入说明。JSONL 保留 document_id、source_url、platform、author_id、title、text、markdown、captured_at、content_hash、partial_content 和图片链接。作者名称和发布时间未可靠提取时为 null；采集时间不能当作发布时间。旧记录的采集时间可能为空。建议入库时按标题／段落切块，再生成向量；可另行使用 MinerU 识别正文图片，不生成 embedding。

### 选择本机保存目录与 Agent 入库

“按作者批量下载”里可选择保存方式：本机文件夹或浏览器 ZIP 下载。点击“选择文件夹”打开本机选择窗口；也可粘贴绝对路径，点击“应用保存位置”。设置保存在本机，刷新和重启后仍保留。“打开保存目录”和每个任务的“打开任务目录”可在资源管理器查看。浏览器下载模式的落盘位置仍由浏览器设置决定。

文件夹模式会在任务结束后自动保存（需勾选自动保存）；已保存部分也可随时点击“保存到本机目录”。目录结构为 `所选目录/平台_作者ID/`，包含累计 documents.jsonl、以文章固定 ID 命名的 Markdown、images、RAG 导入说明及 export.json。同作者的历史任务会在下一次导出时合并，重复文章只保留一条，不变的文件不重写。旧时间戳目录保留作备份，不要递归导入 RAG。微信使用账号 __biz 的哈希区分目录；仅有短文章链接且缺少账号标识时按链接隔离，不猜测作者。人工修改的生成文件在覆盖前备份到 _user_backups；损坏的 JSONL 会报错并保持原文件。

Agent 只导入作者目录根部的 documents.jsonl，读取前后核对 `export.json` 的 `ready=true` 且 `generation` 未变化（变化时重读），并校验 documents_sha256。按 document_id 做 upsert，按 retrieval_hash 判断正文、元数据及 OCR 是否变化，再按标题／段落切块并生成 embedding。documents_count 是本任务导出篇数，author_documents_count 是该作者合并后的累计篇数。发布时间缺失时为 null，不能用采集时间代替；图片识别结果单独保留在 images[].ocr。未生成向量或写入任何向量数据库。


### RAG 数据质量与图片处理

批量任务使用逐篇 SQLite 事务存储；旧 result.json 仍可读取，在首次新增文章时迁移，旧文件不覆盖。页面明确提供的作者、发布时间写入 JSONL，无法确定年份或仅显示相对时间时 published_at 为 null，published_at_raw 保留原始字符串。扩展需更新至独立版 1.5.3 或 Cookie-Editor 本机版 1.14.3 并重新加载，才能保留 head 中的文章元数据。

在作者任务暂停或结束后，可点击“下载正文图片”。后台处理完成后，重新“保存到本机目录”或下载资料包；images 文件夹与 documents.jsonl 保持相对位置。每篇最多 40 张、单图 8 MB、每任务 100 MB，每轮处理最多 30 分钟。不会传递浏览器 Cookie，不追踪图片重定向；失败原因保留在 images[].error，原始图片链接始终保留。失败或中断后可重试，已保存的图片复用。

“识别图片（MinerU）”使用官方云端 VLM，需配置本机 API 凭据。OCR 文本位于 images[].ocr.text，并标记 verified=false。它是机器识别的图中文字，不是图表趋势解释，也不是可靠的原始文章正文。本机 Tesseract 已安装，当前网页默认使用 MinerU。

Agent 入库建议：只读取 export.json 中 ready=true 的完整快照；以 document_id 更新文档，以 retrieval_hash 判断正文、元数据或 OCR 是否发生变化。content_hash 仅用于正文去重。正文按段落切块；OCR 建立独立块，保留 source_url、document_id、图片 URL、图片 SHA256 和 verified=false，引用时可回查原图。partial_content=true 的试读内容应单独标记，不应视为全文。


### MinerU VLM 与精简任务面板

当前作者批量任务的“识别图片（MinerU）”使用官方 mineru.net VLM API。点击后会上传正文图片，在后台识别；完成后点击“保存资料”，JSONL 的 images[].ocr 包含 text、markdown、tables、engine、model、image_sha256、verified。Markdown 文件也附上独立的图片识别段落，原始正文不改写。表格 tables 保留二维单元格数组，股票代码等值保持字符串，入库应连同表头逐行切块。机器识别结果需保留来源图片，不能自动当作已校验数据。

按图片 SHA256 缓存结果；已取得任务 ID 时，查询失败或超时再次点击会继续原任务。云端解析明确失败时，下次手动重试才重新提交。网络中断发生在提交响应返回前，服务端是否受理可能无法确认。单次轮询约两分钟，超时保留任务供后续继续。识别过程中页面可关闭，本机服务需要保持运行。

凭据在当前 Windows 用户的 LocalAppData/UnifiedSpider/mineru-token.dpapi 中加密保存，或从服务环境变量 MINERU_API_TOKEN 读取。不经前端返回，不进入导出文件，也不随便携包分发。更换电脑或 Windows 用户需重新配置凭据。

默认仅展开当前运行／待验证任务；暂停和结束的任务位于“历史任务”，每次展示 20 条。历史任务、详情和保存设置均可展开，页面刷新任务状态时会保留当前展开状态。单网页收集和其他帮助也折叠展示；已有数据未删除。


历史发现与自动处理更新：新版扩展支持下一页、加载更多、内部滚动容器；滚动未到底时不会因 6 轮无新增而结束。只有达到篇数上限或页面连续确认末尾才自动保存正文；卡住时暂停并提示检查，不冒充全部完成。历史任务可在详情中“继续发现历史”，保留已保存文章，从新增链接继续。

新任务默认启用“采集完成后自动识别图片并保存资料”。后端串行排队调用 MinerU，使用任务开始时选择的目录；关闭网页不会中止后处理，服务重启会恢复排队或未完成的后处理。识别失败仍保存成功资料和错误标记，提供“重试识别并保存”。浏览器下载模式需要网页保持打开；需要完全后台保存请选本机目录。该更新需要重新加载 Cookie-Editor 1.14.3 或独立版 1.5.3。


### 并行识别与跨任务文章去重

启用自动处理后，每篇正文成功保存即进入 MinerU 图片队列。图片识别串行控制 API 并发，但与浏览器正文采集并行；OCR 完成不会改变正在采集的任务版本号，避免丢弃浏览器回复。所有正文完成后等待图片队列，再生成最终资料包。手动“识别图片”保留用于旧任务或重试，不是自动任务的必需步骤。

新任务会从本机历史任务的成功文章记录建立链接集合，并在保存前再次核对。按规范化文章 URL 去重，失败或用户跳过的记录不算已保存。界面显示“跳过 N 篇已有文章”；浏览器 ZIP 只包含本次正文，本机作者目录则合并历史与新增正文。原文在同一网址发生修改不会自动重新抓取，不同网址的相似正文也不按内容删除。微信无法确认作者标识时仍可按规范化文章链接去重。同作者相同图片 URL 复用现有本地图片，已成功识别且 SHA256 一致的图片不再调用 MinerU；其他同内容图片也可使用 MinerU SHA256 缓存。暂停正文采集时，已入队的图片仍可继续识别。正文数据库为项目 `data/<任务ID>/articles.sqlite3`，属于本机 SQLite 文件，与用户所选的资料导出目录分开；历史去重依赖这些任务记录，请勿随意删除。

### 快速增量与补齐历史

新任务默认快速增量更新：使用按最新排序的作者列表，连续 3 批新遇到的链接、合计至少 30 篇都已入库时停止向历史翻页。重复轮询同一屏、加载中页面不累计；发现未入库文章会清零连续旧文计数。快速停止属于启发式，不代表历史完整。首次没有历史记录时继续扫描至明确末尾或数量上限。

选择补齐历史会禁用快速停止；旧任务缺少模式字段时沿用完整扫描，重新扫描历史操作也使用补齐历史。只有列表明确到达末尾且未触及篇数上限才记录 history_complete，此字段表示列表扫描结束，不保证文章全部下载成功或平台展示了全部历史。新增正文继续自动图片识别并合并作者目录，无新增时不启动 OCR 或导出。修改后需重新启动后端；前端会检测后端能力，避免静默退回旧逻辑。

### 单篇失败容错

Cookie-Editor 1.14.5 / 独立扩展 1.5.5 配合新版后端：明确删除的文章写入失败清单后跳过；地址跳转、空页面或正文提取失败自动重新导航重试一次，再失败继续下一篇。登录、验证码、访问限制仍暂停；连续三篇普通失败暂停检查，避免整体异常造成批量跳过。失败记录不进入成功去重集合，以后补齐历史仍可重试。新版扩展检测后端能力，后端未重启时会明确提示；不会用首页正文替代文章。
